# Registro de auditorías de seguridad

Historial de auditorías de base de datos y aplicación de Arcade Vault; lo mantiene el subagente `security-auditor` (entradas más nuevas arriba, IDs `SEC-NNN` estables entre auditorías).

## 2026-10-27 — correcciones (SEC-001 a SEC-011)

Aplicadas a petición del usuario tras las dos auditorías. Migración `20261028044422_security_hardening.sql` (aplicada en Supabase): SEC-002 a SEC-004 (revokes y insert por columnas), SEC-005 (default privileges de funciones en `public`) y SEC-006 (`(select auth.uid())`). SEC-001: archivos de `supabase/migrations/` renombrados a las versiones de la base y `scores_insert_authenticated` registrada en el historial como `20261028020000`. SEC-007: la marca huérfana es de `INVITADO`, nombre reservado por el `check` de `profiles`; nadie puede heredarla, se acepta. SEC-008: `next` y `eslint-config-next` a 16.4.3. SEC-009: `X-Forwarded-Host` solo se acepta si coincide con el host de `SITE_URL` (variable opcional; sin ella se usa `origin`). SEC-010: `revalidateScores` exige sesión y valida el id. SEC-011: `poweredByHeader: false`. Verificado: lint y build OK, advisor de seguridad solo con `auth_leaked_password_protection`, advisor de rendimiento sin avisos, `X-Powered-By` ausente y el callback ignora un `X-Forwarded-Host` ajeno. Pendiente: prueba manual de guardar una marca con sesión y definir `SITE_URL` en producción.
